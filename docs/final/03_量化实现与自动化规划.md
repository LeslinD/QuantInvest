# 阶段三：量化实现与自动化规划

阶段目标：把第二阶段形成的金融方案转成课程项目可实现、可复现、可审计的原型实验。本文只讨论如何落地，不重新定义金融逻辑；如果实现中发现数据不可得或定义不可审计，应回到第二阶段修正金融方案。

## 核心结论

当前 `quant_sports_event` 已具备行情抓取、因子计算、事件研究、滚动样本外验证、组合生成和模拟订单输出能力。期末沿用现有流水线，补齐五个短板：

1. 事件库审计：赛事来源、国内关注度、A股映射、证据等级全部结构化。
2. 热度数据层：把“赛事热度”和“标的热度”分开记录，再用匹配度连接。
3. 持仓归因：解释为什么买、为什么不买、为什么仓位变大或变小。
4. 投研闭环：每轮实验都能输出诊断、修改动作、再测试结论。
5. 风控与对冲报告：先做可解释的风险约束和情景分析，原型中不强行做复杂衍生品交易。

阶段三以可复现和可审计为成功标准。老师追问“热度怎么算、数据怎么来、持仓为什么这样、风险如何控制”时，每个数字都能回到数据、公式和配置。

## 自动化边界

| 数据/功能 | 自动化等级 | 处理原则 |
| --- | --- | --- |
| A股行情、成交额、波动率、动量 | 全自动 | 由现有行情模块抓取并冻结快照 |
| 事件窗口收益、CAAR、滚动样本外验证 | 全自动 | 每次运行自动生成，作为策略优劣的实证依据 |
| 赛事基础信息 | 半自动 | 官方赛程可脚本抓取或人工录入，但必须保留官方来源链接 |
| 百度指数、微信指数 | 半自动 | 课程原型允许人工导入，但必须记录日期、关键词和截图索引 |
| 新闻数量、全球新闻热度 | 半自动 | 可用GDELT或新闻搜索接口，缺失时记录 `missing_reason` |
| 东方财富/同花顺热榜 | 半自动 | 人工导入排名即可，禁止把无法复查的主观印象当数据 |
| 公司业务证据 | 人工审核 | 来自年报、官网、公告、赞助新闻；每只股票至少两条证据 |
| 对冲交易 | 分析型输出 | 可用指数、ETF或股指期货做情景说明，原型不强制下单 |

工程原则：自动化优先；无法自动获取的数据用标准模板人工导入。所有人工数据进入审计表，避免散落在文档叙述里。

## 核心实现模块

### 0. 投研闭环控制器

新增 `research_loop.py` 或在 `run_final_pipeline.py` 中实现轻量研究循环控制器。

职责：

| 步骤 | 自动化动作 | 输出 |
| --- | --- | --- |
| `Define` | 读取本轮实验假设和改动模块 | `experiment_registry.csv` |
| `Run` | 冻结配置，运行基线、完整模型、去除对照模型 | 回测和模拟盘输出 |
| `Observe` | 汇总收益、风险、成本、持仓、因子贡献 | `diagnostic_inputs.json` |
| `Diagnose` | 按规则识别失败来源 | `diagnostic_report.md` |
| `Patch` | 生成下一轮行动，不自动改金融假设 | `next_actions.yaml` |
| `Validate` | 对修改后版本重新运行同样实验 | 新一轮实验记录 |
| `Decide` | 标记接受、回滚或观察 | `iteration_log.csv` |

课程原型保留人工确认环节。系统自动生成诊断和行动清单，用户确认后再修改配置，避免程序无限搜索参数。

### 1. 事件库审计

新增 `event_library.py`，对 `events_sports_final.json` 做入库检查。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `event_id` | 稳定ID，如 `fifa_world_cup_2026` |
| `event_name` | 赛事中文名 |
| `start_date` / `end_date` | 事件窗口锚点 |
| `event_type` | 足球、篮球、综合赛事、冰雪、电竞等 |
| `china_attention_level` | 国内关注度评分 |
| `a_share_chain_tags` | 电视、营销、草坪、场馆、健身、传媒、旅游等链条 |
| `event_fit_prior` | 赛事对A股股票池的先验匹配度 |
| `tradable_flag` | 是否适合纳入交易实验 |
| `source_urls` | 官方和权威来源 |
| `review_note` | 入库、观察或剔除理由 |

审计规则：

| 规则 | 不通过时处理 |
| --- | --- |
| 至少一个官方赛程来源 | 不入库 |
| 至少一个国内关注度或商业价值来源 | 入观察库，不进入交易 |
| A股链条为空 | 不进入交易 |
| 赛事时间晚于模拟交易日期太远且无预期催化 | 只做规划，不进回测 |
| 综合赛事 `event_fit_prior < 0.60` | 降权或仅做对照样本 |

该模块回应老师关于“事件太少、缺乏系统性”的意见。

### 2. 热度数据层

新增 `attention.py`，把热度定义拆成三层。

```text
EventHeat = z(BaiduIndex) + z(WeChatIndex) + z(NewsCount) + z(MediaTopicCount)
StockHeat = z(AmountShock) + z(TurnoverProxy) + z(HotRankChange) + z(ForumCount)
HeatStockFit = EventHeat * StockHeat * StockFit * DirectionGate
```

解释标准：

| 指标 | 金融含义 | 数据来源 |
| --- | --- | --- |
| `BaiduIndex` | 大众搜索关注 | 百度指数人工导入 |
| `WeChatIndex` | 国内社交传播 | 微信指数人工导入 |
| `NewsCount` | 媒体覆盖 | GDELT或新闻搜索 |
| `MediaTopicCount` | 财经媒体讨论 | 财经新闻/热榜导入 |
| `AmountShock` | 市场资金关注 | 行情成交额相对过去60日均值 |
| `TurnoverProxy` | 交易拥挤程度 | 成交额、市值或换手率近似 |
| `HotRankChange` | 财经平台热榜变化 | 人工导入 |
| `ForumCount` | 投资者讨论 | 股吧或互动平台计数，缺失则审计 |
| `StockFit` | 业务与赛事匹配度 | 阶段二金融评分 |
| `DirectionGate` | 正负方向过滤 | 过热、监管、业绩风险时降为0或小于1 |

所有热度数据必须有 `as_of_date`、`source_name`、`query_keyword`、`raw_value`、`normalized_value`、`source_url_or_file`、`missing_reason`。部分热度即使只能半自动导入，也能解释“如何拿到数据”。

### 3. 事件-标的暴露

扩展股票池配置，给出可审计评分，避免只写“与体育相关”。

| 字段 | 定义 |
| --- | --- |
| `business_relevance` | 主营业务与赛事链条的直接程度 |
| `event_evidence_score` | 年报、公告、官网、官方赞助新闻的证据强度 |
| `attention_comovement` | 赛事热度上升时股票成交额/热榜是否同步 |
| `tradability_score` | 流动性、波动、涨跌停风险 |
| `risk_quality` | 业绩、估值、主题拥挤、监管风险 |
| `stock_fit` | 加权后的最终匹配度 |

入选交易池的最低门槛：

| 门槛 | 数值 |
| --- | --- |
| `stock_fit` | 不低于0.60 |
| `tradability_score` | 不低于0.60 |
| `event_evidence_score` | 至少两条可复查证据 |
| 未来信息 | 模拟交易日期之后的信息不得进入当期决策 |

### 4. 综合因子构造

新增 `super_factors.py`，先把底层指标合成为五个综合因子，再生成最终信号。

```text
CoreSignal =
  0.25 * EventOpportunity
+ 0.25 * StockLinkage
+ 0.20 * AttentionConfirmation
+ 0.15 * MarketTiming
+ 0.15 * TradableRiskQuality
- RiskPenalty
```

综合因子与当前代码因子的关系：

| 综合因子 | 当前可复用字段 | 新增字段 |
| --- | --- |
| `EventOpportunity` | `event_fit`、事件日期 | 官方确定性、国内关注度、赛事层级、生命周期 |
| `StockLinkage` | `exposure` | 链条等级、证据强度、事件特异性 |
| `AttentionConfirmation` | `attention` | 赛事热度、新闻量、热榜、股吧讨论、共振分 |
| `MarketTiming` | `momentum`、`event_time_score` | 短期反转、过热惩罚 |
| `TradableRiskQuality` | `liquidity`、`low_volatility` | 成本、涨跌停、行业集中度、风险标记 |

权重治理规则：

| 规则 | 实现方式 |
| --- | --- |
| 初始权重来自金融先验 | 写入 `strategy_final.json` |
| RankIC 只做收缩校准 | 保留 `estimate_constrained_rankic_weights`，但限制权重上下限 |
| 单轮迭代权重变动不超过 5 个百分点 | 在 `research_loop.py` 检查 |
| 新增因子必须有去除对照实验 | 输出 `ablation_result` |
| 高热度低匹配不得高仓位 | `StockLinkage` 门槛和 `RiskPenalty` 双重控制 |

底层因子可以继续迭代；答辩时解释五个稳定综合因子，避免展示一串临时变量。

### 5. 组合与风险

组合约束写入 `strategy_final.json`，由 `portfolio.py` 自动执行。

| 约束 | 数值 | 理由 |
| --- | --- | --- |
| 单票上限 | 10%-12% | 与中期保持可比，避免单一主题股票支配结果 |
| 单事件上限 | 20%-30% | 防止世界杯等单事件过度集中 |
| 单行业上限 | 20%-25% | 防止传媒、体育服务或硬件过度集中 |
| 现金底线 | 不低于60% | 保持课程模拟交易的风险可控性 |
| 观察仓上限 | 单票3%-5% | 证据不足但有跟踪价值的标的只做小仓位 |
| 止损 | 单票或组合触发 | 使用现有止损模块，输出触发理由 |
| 过热降仓 | 热度极高但匹配度不足时 | 解决“奥运会热度高但标的不匹配”的问题 |

对冲报告可先做三类情景分析：

| 情景 | 报告内容 |
| --- | --- |
| 市场系统性下跌 | 用沪深300/中证500代理估计组合Beta风险 |
| 主题退潮 | 对高热低匹配标的做降仓前后对比 |
| 事件不及预期 | 赛事窗口后收益回吐情景，给出止盈/止损规则 |

课程原型可不真实买入股指期货或 ETF，但需要说明“不下单原因”和“需要对冲时的处理方式”。

### 8. 归因诊断与下一轮提升

新增 `diagnostics.py`，把回测和模拟盘结果转成下一轮行动。

诊断规则：

| 诊断标签 | 触发条件 | 动作 |
| --- | --- | --- |
| `event_misfit` | 赛事热度高，但关联股票整体 CAAR 弱 | 降低事件层级或只保留观察 |
| `stock_mapping_gap` | 未入选股票表现好，但证据缺失 | 回到股票池补证据，权重保持冻结 |
| `attention_overheat` | 热度高、短期涨幅高、后续回撤大 | 提高过热惩罚或提前退出 |
| `factor_noise` | 去掉某因子后结果更好 | 降权或移入观察因子 |
| `risk_concentration` | 收益改善但集中度或回撤恶化 | 降低单票/行业/事件上限 |
| `data_quality_gap` | 热度、证据或行情字段缺失 | 降级为人工导入或剔除本轮样本 |
| `small_sample_warning` | 结果来自少数事件或少数交易 | 标记为探索结论，不能作为强结论 |

`diagnostic_report.md` 应包含：

1. 本轮假设是否被支持。
2. 收益、风险、解释力分别变化多少。
3. 哪些持仓贡献了收益，哪些拖累。
4. 哪些因子通过去除对照实验，哪些可能是噪声。
5. 下一轮只允许修改哪些模块。
6. 是否接受本轮修改。

| `test_lot_size_after_risk_scaling` | 风险缩放后仍满足A股100股交易单位 |
| `test_attribution_sums` | 各因子贡献能合计回总分或解释残差 |
| `test_hedge_report_is_analysis_only` | 对冲报告不生成未经确认的真实交易订单 |
| `test_super_factor_weight_bounds` | 综合因子权重不突破金融先验上下限 |
| `test_iteration_log_required_fields` | 每轮实验必须记录假设、改动、指标和结论 |
| `test_迭代闭环_acceptance_gate` | 只有通过收益/风险/解释力门槛的修改才能标记接受 |

## 结项展示素材

最终 PPT 或展示按八页组织：

1. 研究问题：体育大事件是否能形成A股事件驱动交易机会。
2. 中期问题：事件少、热度定义弱、持仓归因不足、风控不足。
3. 事件库升级：从4个事件扩展为系统化赛事库，并给出剔除逻辑。
4. 热度指标：赛事热度、标的热度、热度匹配三层定义。
5. 金融方案：核心/观察/剔除股票池和仓位原则。
6. 期末模拟交易：订单、仓位、成本和中期对比。
7. 回测与归因：收益、回撤、CAAR、去除对照实验和持仓解释。
8. 风险与总结：风险控制、对冲可行性、项目局限和下一步。

## 阶段三审阅门槛

| 审阅问题 | 达标标准 |
| --- | --- |
| 是否尊重金融方案？ | 代码只实现阶段二结论，不反向改写金融逻辑 |
| 是否可复现？ | 从配置、数据、命令到输出都有路径 |
| 是否解释热度？ | 赛事热度、标的热度和匹配热度都有数据定义 |
| 是否解释持仓？ | 每只持仓都有因子贡献、仓位变化和风险说明 |
| 是否比较中期？ | 主观组合、代码基线和期末组合三者可并列表达 |
| 是否有风控？ | 单票、事件、行业、现金、止损和对冲情景都有报告 |
| 是否避免过度实现？ | 无法自动化的数据进入人工导入模板和审计表 |
| 是否形成闭环？ | 至少完成一次“诊断 -> 修正 -> 再测试 -> 审阅”的 迭代闭环 |

任一项不达标时，按问题类型回退：数据定义问题回阶段一，金融逻辑问题回阶段二，工程实现问题留在阶段三修正。
