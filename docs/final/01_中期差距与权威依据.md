# 阶段一：中期差距与权威依据

阶段目标：说明中期之后的提升原因，不进入代码实现细节。结论需经受金融课程老师从理论、数据、持仓解释、风控四个角度审阅。

## 核心结论

中期系统已经具备原型能力，金融解释链仍不完整：热度、事件适配、标的选择、仓位、风控和归因没有形成可审计闭环。期末系统定位为“体育事件热度-适配度驱动的 A 股模拟投资框架”。

中期代码能跑通；期末需要证明每一次交易在金融上可解释。

## 中期材料事实

### 中期报告分析

中期报告更像一个金融课堂方案：用“预期差”解释体育大事件，用 2022 世界杯做单次案例，强调提前布局、聚焦龙头、纪律止盈、总仓位上限 50%。模拟配置页给出 4 只主观标的：舒华体育、粤传媒、元隆雅图、海信视像。

优点是讲得直观，问题是过于主观：为什么是这些标的、为什么是这些权重、热度如何量化、奥运会是否也适配 A 股，都没有充分展开。

### 代码和测试分析

后续测试与代码已经演化成可运行原型：

| 项目 | 中期代码现状 |
|---|---|
| 事件库 | 4 个事件：2022 世界杯、2024 欧洲杯、2024 巴黎奥运会、2026 世界杯 |
| 股票池 | 10 只 A 股候选标的 |
| 因子 | 事件暴露、成交额注意力、动量、流动性、低波动 |
| 模拟盘 | 2026-05-26 决策，2026-05-27 订单 |
| 当前模拟持仓 | 海信视像 12.00%、共创草坪 3.50%、中体产业 2.59%，总目标仓位 18.09% |
| 回测摘要 | 净收益率 11.04%，滚动样本外验证净收益率 2.30%，交易数较少 |

代码分析比中期报告更接近真实交易，也暴露出新问题：热度主要来自成交额冲击，缺少赛事社会关注度；事件库和股票池太小；模拟持仓缺少对比和归因。

## 权威方法给出的约束

| 权威依据 | 对本项目的要求 |
|---|---|
| MacKinlay 事件研究法 | 不能只看股价涨跌，必须用市场模型、AR/CAR 或超额收益证明事件窗口有效 |
| Edmans, Garcia & Norli 体育情绪研究 | 体育事件会影响市场情绪，但情绪影响不等同于某个 A 股公司基本面受益 |
| Barber & Odean 注意力研究 | 新闻、异常成交量、极端收益等能吸引散户注意，但注意力可能导致追高 |
| Da, Engelberg & Gao 搜索注意力研究 | 搜索热度能更直接度量主动关注，且可能出现短期上涨、长期反转 |
| Jegadeesh & Titman、Carhart 动量研究 | 中短期动量可作为信号，但必须控制反转、成本和样本外稳定性 |
| Fama-French 风格因子 | 需要解释收益是否只是市场、规模、风格或行业暴露 |
| Harvey, Liu & Zhu 因子多重检验 | 不能随意增加“看起来有效”的新因子，新增因子必须有经济含义和样本外验证 |
| Bailey 等回测过拟合研究 | 小样本策略不能只看最优回测结果，应记录尝试次数、去除对照实验和滚动样本外验证 |
| MLOps/闭环工程思想 | 系统需要把验证结果反馈到数据、因子、组合和风控模块 |
| 上交所交易机制 | A 股买入必须符合 100 股整数手、涨跌幅限制等真实交易约束 |

期末文档需要把“热度高”拆成可验证链条：

`事件确定性 -> 国内关注度 -> A股产业链适配 -> 标的证据 -> 热度启动 -> 风险约束 -> 持仓与归因`

## 新增治理差距

从专业投资者和量化投资人的角度看，原方案还需要补三类“研究治理”问题。

| 新增审阅问题 | 当前风险 | 期末修正 |
|---|---|---|
| 综合因子如何确定 | 只给公式会显得主观设定过强，老师会追问权重来源 | 将因子分成事件机会、标的映射、注意力确认、市场时机、可交易风控五个综合因子，并说明文献、业务先验和回测校准边界 |
| 选股对应如何证明 | 体育概念容易泛化，尤其元隆雅图、粤传媒、舒华体育等并不必然受世界杯驱动 | 按 L1 直接链条、L2 强间接链条、L3 注意力链条、L4 泛体育概念、L5 噪声误配分层 |
| 回测之后如何提升 | 现在更像线性方案，缺少“跑完后如何分析错误并修正”的机制 | 建立 `Define -> Run -> Observe -> Diagnose -> Patch -> Validate -> Decide` 循环 |

体育事件样本少，评审容易质疑过拟合。方案需要写清“为什么这样改”和“改完如何验证”，把优化过程约束为投研迭代。

## 差距矩阵

| 审阅问题 | 中期现状 | 期末必须补足 |
|---|---|---|
| 热度如何计算、数据从哪里来 | 主要用 `log(成交额) - log(MA成交额)`，只能代表个股交易热度 | 拆成事件热度、个股热度、热度-标的匹配度；保留数据来源、时间戳和人工/自动标记 |
| 奥运会等综合赛事热度很高但标的是否匹配 | 2024 巴黎奥运会被放入事件库，但 `event_fit` 解释不足 | 建立“国内关注度 × A 股产业链适配”的门控，低适配事件不强行高仓位 |
| 事件库太少 | 历史事件只有 3 个，样本不足 | 系统梳理足球、综合赛事、冰雪、篮球、国内赛事、前置节点 |
| 股票池太窄 | 10 只，且证据多为公司网站概括 | 扩展为候选链条库；每个标的至少有业务、赛事、热度、交易可行性四类证据 |
| 持仓分析不足 | 有订单表，但缺少优化前后、行业、因子、风险、收益贡献对比 | 输出持仓对比表、因子贡献表、收益归因瀑布图、未入选原因 |
| 风控与对冲不足 | 有仓位上限和止损，但对冲只是隐含现金 | 明确现金对冲为基础方案，指数/股指期货对冲为课程分析方案 |
| 回测可解释性不足 | 小样本收益好看，但泛化证据弱 | 统一基准、事件窗口、去除对照实验、滚动样本外验证和样本外说明 |
| 中期主观方案与代码标准不一致 | 中期主观方案是 50% 四股仓位；代码是 18.09% 三股量化订单 | 期末必须说明“中期主观方案”和“中期代码基线”两个基线，分别对比 |
| 投研闭环不足 | 跑完回测后没有明确诊断和下一轮修改机制 | 建立迭代日志、失败分类、修改门槛和再验证流程 |

## 阶段一目标定义

阶段一给后两阶段划边界：

1. 金融设计阶段要优先追求理由完整、可解释、可审计。
2. 计算机实现阶段只需要把核心逻辑自动化到课程原型可复现的程度。
3. 自动化做不到的数据，需要以模板、截图、人工确认和审计表保留，避免伪装成自动数据。

## 高水平审阅门槛

进入阶段二前，方案必须通过以下检查：

| 检查项 | 判定 |
|---|---|
| 是否把“赛事社会热度”和“个股交易热度”拆开 | 通过 |
| 是否解释“热度高但 A 股适配弱”的情况 | 通过 |
| 是否承认样本少、不能夸大收益稳定性 | 通过 |
| 是否明确持仓分析和归因是期末核心任务 | 通过 |
| 是否把金融方案和自动化实现拆开 | 通过 |
| 是否新增“回测-归因-修正-再测”的闭环要求 | 通过 |

阶段一结论：下一阶段从真实数据和现实金融逻辑出发设计最终金融方案。
