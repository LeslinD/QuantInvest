# 模块化投研闭环总设计

本文是期末方案的总地图。三阶段文档分别回答“差距在哪里、金融方案是什么、系统怎么实现”，本文回答“整个投研系统如何循环提升”。

## 方案定位

当前方案的核心方向正确：体育大事件可以作为事件驱动研究对象，A 股组合必须同时解释赛事热度、标的匹配、交易热度、风险约束和持仓归因。

当前方案需要补齐投研系统的治理规则：

| 问题 | 专业审阅会追问 | 补强原则 |
|---|---|---|
| 综合因子来源不明 | 为什么这些因子能合成最终分数，权重是否只是主观设定 | 因子分为文献支持、业务先验、回测校准三类，权重只能在约束内微调 |
| 选股映射偏概念化 | 这只股票和赛事到底有什么收入、订单、关注度或交易关系 | 用直接链条、间接链条、注意力链条、噪声链条分层 |
| 回测后没有学习机制 | 跑完发现效果不好，下一轮改什么 | 建立诊断分类和实验登记，只有通过再验证的修改才能固化 |
| 过拟合风险未显式控制 | 小样本体育事件很容易调出好看的回测 | 使用滚动样本外验证、去除对照实验、参数冻结、变更记录和样本外优先原则 |
| 持仓归因还不够可复盘 | 为什么中期买A，期末买B，仓位怎么变 | 输出单股归因、未入选原因、权重变化原因和风险贡献 |

## 模块化流程

```text
M0 研究章程
  -> M1 事件库
  -> M2 标的映射
  -> M3 热度与行情数据
  -> M4 综合因子构造
  -> M5 组合与风控
  -> M6 回测与模拟盘
  -> M7 归因诊断
  -> M8 迭代决策
  -> 回到 M1/M2/M3/M4/M5 中的具体模块
```

| 模块 | 输入 | 输出 | 审阅问题 |
|---|---|---|---|
| M0 研究章程 | 课程要求、老师意见、中期结果 | 研究目标、交易边界、评价指标 | 目标是否聚焦金融可解释，收益排序只作为评价之一 |
| M1 事件库 | 官方赛程、体育产业政策、历史事件 | 赛事分层、交易/观察/剔除状态 | 事件是否系统、权威、可复查 |
| M2 标的映射 | 公司业务、公告、官网、新闻、历史价格 | 股票池、链条标签、证据等级 | 标的和赛事是否真相关 |
| M3 热度与行情数据 | 百度/微信/新闻/热榜、成交额、价格 | 赛事热度、股票热度、数据审计表 | 热度如何计算，缺失如何处理 |
| M4 综合因子构造 | M1-M3 输出、基础因子、理论先验 | 综合因子分数、因子贡献 | 因子是否有金融含义，是否过拟合 |
| M5 组合与风控 | 综合因子、约束、成本、风险预算 | 目标权重、订单、风控报告 | 仓位是否可交易、可解释、可控 |
| M6 回测与模拟盘 | 配置、行情、组合规则 | 回测、滚动样本外验证、模拟订单 | 优化是否优于中期，且风险没有同步恶化 |
| M7 归因诊断 | 交易、持仓、因子、事件窗口 | 单股归因、失败分类、改进行动 | 好坏来自哪里 |
| M8 迭代决策 | 诊断结果、审阅门槛 | 下一轮修改清单、冻结版本 | 是否值得改，改完如何验证 |

## 综合因子管理

综合因子把多个低层指标按金融逻辑合成为中层信号。答辩时解释持仓，需要说明赛事确定性、标的匹配、热度共振、价格状态和风险约束，并同步列出 `alpha_score`。

### 综合因子定义

| 综合因子 | 低层指标 | 金融含义 | 依据 |
|---|---|---|---|
| `EventOpportunity` | 官方确定性、国内关注度、赛事层级、事件生命周期 | 事件本身是否值得研究 | 事件研究要求先定义事件和窗口 |
| `StockLinkage` | 业务相关、官方合作、收入链条、证据强度 | 股票是否真的受赛事影响 | 防止“概念股”泛化 |
| `AttentionConfirmation` | 赛事搜索热度、新闻量、成交额冲击、热榜、讨论度 | 社会热度是否传导到股票交易 | 投资者注意力研究支持搜索、新闻、异常成交量 |
| `MarketTiming` | 事件前天数、动量、短期反转、过热惩罚 | 什么时候进入或降仓 | 动量有效但需防止追高与反转 |
| `TradableRiskQuality` | 流动性、波动、成本、涨跌停、行业集中度 | 能不能以合理风险交易 | A 股交易约束和组合风控要求 |

最终信号公式：

```text
CoreSignal =
  0.25 * EventOpportunity
+ 0.25 * StockLinkage
+ 0.20 * AttentionConfirmation
+ 0.15 * MarketTiming
+ 0.15 * TradableRiskQuality
- RiskPenalty
```

该公式作为期末原型的初始投资委员会先验。小样本回测用于校准参数，不推翻基本金融逻辑。

### 权重确定规则

| 权重来源 | 使用方式 | 约束 |
|---|---|---|
| 文献支持 | 事件研究、注意力、动量、风格风险提供方向 | 决定因子是否可进入 |
| 业务先验 | 体育赛事链条、国内关注度、A 股可交易性 | 决定初始权重和门槛 |
| 历史回测 | RankIC、滚动样本外验证、去除对照实验 | 只能在上下限内微调 |
| 审阅反馈 | 老师意见和人工证据复核 | 可修改数据定义或降级因子 |

权重约束：

| 约束 | 原因 |
|---|---|
| `EventOpportunity + StockLinkage` 合计不低于 45% | 项目以事件驱动为主，普通量价因子只做辅助 |
| `AttentionConfirmation` 不超过 25% | 注意力可能带来追高和反转 |
| `MarketTiming` 不超过 20% | 避免策略退化为纯动量 |
| `TradableRiskQuality` 不低于 10% | 保证模拟订单可交易 |
| 单次迭代权重变动不超过 5 个百分点 | 防止为了回测结果剧烈调参 |

## 选股映射规则

选股从赛事链条向股票映射，避免先列股票再补理由。

| 映射等级 | 判定标准 | 仓位处理 |
|---|---|---|
| L1 直接链条 | 官方赞助、赛事供应商、明确订单、主营业务直接对应 | 可进入核心池 |
| L2 强间接链条 | 产品/服务与观赛、场馆、体育运营高度相关，有历史热度共振 | 可进入交易池，仓位低于 L1 |
| L3 注意力链条 | 社会讨论强，但收入链条弱或间接 | 观察或小仓验证 |
| L4 泛体育概念 | 只有概念标签，无当期证据 | 不交易 |
| L5 噪声/误配 | 热度来自非赛事原因，或标的与赛事方向相反 | 剔除 |

每只股票至少记录：

| 字段 | 要求 |
|---|---|
| `chain_level` | L1-L5 |
| `evidence_items` | 至少两条证据，含日期和来源 |
| `event_specificity` | 证据指向本次赛事，避免泛体育叙述 |
| `attention_sync` | 赛事热度和股票热度是否同向 |
| `risk_flags` | 业绩、估值、流动性、监管、涨跌停、过热 |
| `decision` | 核心、交易、观察、剔除 |
| `decision_reason` | 一句话说明 |

## 迭代闭环工程 落地

本项目把迭代闭环方法落成量化投研循环：行动、观察、评价、修正、再行动。

```text
1. Define：写清本轮假设
2. Run：冻结配置并运行回测/模拟盘
3. Observe：生成收益、风险、归因、持仓和数据质量报告
4. Diagnose：把问题归类到事件、标的、热度、因子、组合、风控或数据
5. Patch：只修改对应模块，并记录改动理由
6. Validate：重新跑基线、完整模型、去除对照实验和滚动样本外验证
7. Decide：通过则冻结版本，不通过则回滚或降级为观察项
```

### 诊断分类

| 现象 | 可能原因 | 下一轮动作 |
|---|---|---|
| 回测收益好，滚动样本外验证差 | 参数或因子过拟合 | 缩小参数网格，提高先验权重，降低模型自由度 |
| 赛事热度高但组合亏损 | A 股链条不匹配，或预期已兑现 | 提高 `StockLinkage` 门槛，增加过热惩罚 |
| 个股涨幅好但未入选 | 股票池证据或热度数据漏采 | 回到 M2/M3 补证据，权重保持冻结 |
| 入选个股亏损集中 | 行业/事件/单票暴露过高 | 回到 M5 降低集中度，提高现金或对冲 |
| 收益来自少数一次交易 | 样本太少或偶然性高 | 标记为探索结论，不作为核心证明 |
| 去掉某因子后结果更好 | 因子可能是噪声 | 降权、设为观察因子或删除 |
| 解释力提升但收益略降 | 金融方案更稳健 | 可保留，但要在展示中说明风险收益取舍 |

### 实验登记

每轮实验生成 `outputs/final/iteration_log.csv`：

| 字段 | 说明 |
|---|---|
| `iteration_id` | 如 `first_iteration_001` |
| `hypothesis` | 本轮要验证的改进 |
| `changed_module` | M1-M8 中哪个模块变了 |
| `changed_files` | 配置或代码文件 |
| `baseline_version` | 对比基线 |
| `metrics_before` / `metrics_after` | 收益、回撤、夏普、换手、成本、解释力 |
| `ablation_result` | 因子是否真的贡献 |
| `decision` | 接受、回滚、观察 |
| `review_note` | 人工审阅结论 |

### 通过门槛

一次修改通过前，需要满足下面两类条件之一：

| 通过类型 | 条件 |
|---|---|
| 性能提升 | 滚动样本外验证或样本外事件表现改善，且最大回撤、成本、集中度没有明显恶化 |
| 解释提升 | 收益不显著改善，但持仓理由、风险控制、数据定义明显更可审计 |

若收益提升来自更高仓位、更高集中度或更多调参次数，应标记为“高过拟合风险”，不作为期末主结论。

## 期末最小闭环

课程时间约束下，完成一个高质量最小闭环：

1. 冻结中期代码基线。
2. 建立期末事件库和股票映射。
3. 导入或半自动记录热度数据。
4. 运行期末完整模型。
5. 输出中期/期末持仓对比。
6. 输出归因诊断。
7. 根据诊断做一次有理由的修正。
8. 再跑一次并说明修正是否通过。

完成这八步后，期末答辩可以展示系统的运行、诊断和迭代能力。该证据比增加更多事件或更多因子更有说服力。
